TMDB API Developer Guide

An API documentation project covering 52 operations across 51 paths of The Movie Database (TMDB) API. The project involved testing each endpoint in Postman, developing and refining an OpenAPI 3.0 specification, and publishing the documentation as a developer reference on Mintlify.

The problem

API documentation can look complete while still containing gaps between documented behavior and what an API actually returns.

This project focused on closing that gap through hands-on API testing rather than relying solely on existing documentation. The goal was straightforward: create documentation that gives developers enough information to work with the API without guessing.

What I built

The TMDB API Developer Guide covers 52 operations across 51 paths, including authentication, accounts, search, discover, movies, networks, and related resources.

The project started in Postman, where I tested each endpoint against the live API. Testing covered:

  • Request paths, query parameters, and request bodies
  • Authentication and session requirements
  • Successful responses and response structures
  • Error responses and status codes
  • Dependencies between authentication and session endpoints

After testing, I used the documented results to generate an OpenAPI 3.0 specification. Next, I reviewed and refined the spec in VS Code and Swagger Editor. The review process included correcting malformed paths, standardizing operation IDs, verifying path parameters and request bodies, modeling reusable response structures, and rewriting endpoint descriptions.

The Workflow

  • Explore & test: Test all endpoints in Postman, including authentication flows, request parameters, request bodies, successful responses, and error behavior.
  • Generate specification: Use the tested and documented Postman collection to generate an initial OpenAPI 3.0 specification.
  • Review the structure: Inspect the spec for structural issues, like malformed paths, inconsistent operation IDs, missing or incorrect parameters, request-body definitions, and authentication requirements.
  • Model reusable schemas: Structure shared responses as reusable OpenAPI components rather than duplicated across individual endpoints. This involved structures for movies, people, search results, pagination, and errors.
  • Refine the documentation: Review descriptions, terminology, examples, and authentication requirements against the tested API behavior.
  • Validate and publish: Check the finished specification in Swagger Editor and publish it as the API reference for developers on Mintlify.

Why it matters

The value of this project is in the process: test the API, compare actual behavior with the available documentation, model the findings in OpenAPI, and validate the finished specification before publication.

The Postman collection provides the testing record, while the OpenAPI specification captures the resulting documentation model. Together, they make the work inspectable rather than relying on the published reference alone.
